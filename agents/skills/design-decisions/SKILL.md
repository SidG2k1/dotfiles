---
name: design-decisions
description: "Use when a technical design choice is still open or the user asks which approach to take. Compares the options by effort, reversibility, and tradeoffs, and names the evidence that would change the recommendation."
---

Identify the actual decision and constraints from current requirements, code, and accepted decisions. Resolve factual questions yourself before asking the user to choose.

For credible alternatives, compare benefits, drawbacks, implementation and operational effort, reversibility, and remaining uncertainty. Recommend one and explain what evidence would change that recommendation. Use a table when it makes alternatives easier to compare.

If probabilities are requested, label them as subjective judgments and explain the important assumptions; do not imply empirical calibration. Preserve credible alternatives in an existing design record when the user requests an update. Keep settled decisions out of the active question list unless new evidence warrants reopening them.

Do not start implementation, update trackers, or create a new design file merely because a comparison was requested.
